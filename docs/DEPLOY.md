# Putting Vale online

Backend on **Render** (free), frontend on **Vercel** (free), accounts, reader data and
story pictures in **Supabase**, email through **Brevo**, the 7am wake-up from
**cron-job.org**. About 20 minutes. Keys come from your local `backend/.env` and
`frontend/.env`. Never paste the Supabase *secret* key into Vercel.

## 1. Backend on Render

1. Go to https://render.com, sign in with GitHub.
2. **New → Blueprint**, pick the `personal-morning-paper` repo. Render reads `render.yaml`
   and proposes a web service called **vale-api**.
3. It asks for the secret values. Copy them from `backend/.env`:
   `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`,
   `BREVO_API_KEY`, `MAIL_FROM_EMAIL`.
   For `PUBLIC_APP_URL`, `ALLOWED_ORIGINS` and `PUBLIC_API_URL`, type `http://localhost:5173`
   for now; you will fix them in step 3 once you know the real addresses.
   (`LINK_SECRET` and `CRON_SECRET` are generated by Render.)
4. **Apply**. The first build takes 3–5 minutes. When it says *Live*, copy the address at the
   top, e.g. `https://vale-api.onrender.com`. Opening `<that address>/api/health` should show
   `{"ok":true}`.

## 2. Frontend on Vercel

1. Go to https://vercel.com, sign in with GitHub, **Add New → Project**, import the same repo.
2. **Root Directory: `frontend`** (Framework: Vite is detected).
3. **Environment Variables** (from `frontend/.env`, plus the Render address):
   - `VITE_API_BASE` = your Render address (no trailing slash)
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `VITE_COPILOTKIT_PUBLIC_API_KEY`
4. **Deploy**. Copy the site address, e.g. `https://vale-paper.vercel.app`.

## 3. Tell each service about the others

- **Render → vale-api → Environment**: set
  `PUBLIC_APP_URL` = the Vercel address,
  `ALLOWED_ORIGINS` = the Vercel address,
  `PUBLIC_API_URL` = the Render address. Save (Render redeploys by itself).
- **Supabase → Authentication → URL Configuration**:
  *Site URL* = the Vercel address; *Redirect URLs* → add `https://<your-vercel-address>/**`.
  Keep `http://localhost:5173/**` too, for local work.
- **Copilot Cloud** (https://cloud.copilotkit.ai): if the Editor chat refuses to connect from
  the live site, add the Vercel address to the allowed origins of your public key.

## 4. The 7am morning paper (cron-job.org)

Render's free server sleeps after 15 minutes without visitors, so something must wake it.

1. https://cron-job.org → sign up → **Create cronjob** twice:
   - **Wake up**: URL `<Render address>/api/health`, every day **06:50**, timezone
     *Asia/Karachi*.
   - **Send papers**: URL `<Render address>/api/cron/daily`, every day **07:00**,
     timezone *Asia/Karachi*. Under *Advanced*: request method **POST**, add header
     `X-Cron-Secret` = the `CRON_SECRET` value from Render → Environment.
2. The send job may show "timeout" in cron-job.org: that is fine, the server keeps working
   after the request ends. Every reader gets at most one morning email a day.

## 5. Check it

1. Open the Vercel address on your phone, sign in with your email link.
2. Your paper prints (the first visit after a sleep takes ~50 s while Render wakes up).
3. Tap **You → Send this paper to my email** and check the inbox: PDF attached, links work.
4. Download the PDF and scan a QR code.

## What lives where

| Thing | Where | Survives restarts |
|---|---|---|
| Accounts | Supabase Auth | yes |
| Each reader's profile, weights, editions | Supabase table `vale_readers` | yes |
| Story pictures | Supabase Storage bucket `vale-images` (private, served by the API) | yes |
| Publisher logos | Render disk (re-fetched after a restart) | cache only |
